Stage 1: CSV To Graph

graph LR A[training_data.csv
Machine = active] --> B[generate_graphs.py] B --> C[Detect run boundaries] C --> D[Parse PTT tree growth] D --> E[Build Agent / Search / Track nodes] E --> F[Add 4 edge types] F --> G[active_graph.json + active_graph.html]

Stage 1 Input

Machine: active
PTT grows from:
1 Reconnaissance
1.3 Identify Open Ports, Services running on the open ports and their versions
1.6 SMB Enumeration
1.7 Replication Share Enumeration
1.8 Hash Decryption
...

Stage 1 Output

Example nodes:
- agent:active:START
- search:active:r1_s1_1.6  -> SMB Enumeration
- track:active:r1_s1_1.6   -> anonymous login, shares, SMB status

Example edges:
- StateTransition
- SearchUpdate
- TrackUpdate
- Prediction

Implementation Detail

generate_graphs.py turns PTT growth into a state graph. Agent nodes store the cumulative pentest state, Search nodes store the tree item being worked on plus MCP calls, and Track nodes store the findings discovered from that step.

Stage 2: Graph To Embeddings

graph LR A[active_graph.json] --> B[graph_to_embeddings.py] B --> C[Node text] B --> D[Edge text] C --> E[Sentence-BERT] D --> E E --> F[Node embeddings] E --> G[Edge embeddings] B --> H[Consecutive CSV rows] H --> I[step_pairs] F --> J[active_processed.json] G --> J I --> J

label: Agent: Initial (Start)
title: Start of pentest against 'active'

Edge example:
type: SearchUpdate / TrackUpdate / Prediction

Implementation Detail

graph_to_embeddings.py embeds node text and edge text with all-MiniLM-L6-v2. The resulting JSON stores both graph embeddings and step-pair supervision in one place, which is what the trainer consumes later.

Stage 3: Training Sample Construction

graph LR A[active_processed.json] --> B[PenTestDataset] B --> C[Build context text] B --> D[Normalize Next Step label] B --> E[Normalize MCP tool set] C --> F[Prompt with GRAPH token] D --> G[Target tags] E --> G F --> H[train_gnn_rl.py] G --> H

Trainer Input

[GRAPH]
Previous Strategy: Enumerate the SMB service in port 445
Previous Strategy Explanation: ...
Previous Step: Enumerate further on the X service...
Previous Step Explanation: ...

Trainer Target

Next Step: Explore the suspicious files, commands and create a summary of the findings.
MCP Tools: Smb client, Interactive CLI
Next Step Explanation: ...

Implementation Detail

The current trainer constrains Next Step and MCP Tools to fixed label sets, while still generating an explanation. It also uses edge embeddings now, not just node embeddings and graph connectivity.

Stage 4: Model Internals

graph TD A[Node embeddings] --> D[GNN] B[Edge embeddings] --> E[Edge projection + pooling] C[Previous context text] --> F[Sentence-BERT + projection] D --> G[Combined state] E --> G F --> G G --> H[Replace GRAPH token embedding] H --> I[LLM output] G --> J[Step classifier] G --> K[MCP multi-label classifier]

Implementation Detail

The policy combines three signals: graph state from the GNN, pooled edge-embedding state, and previous context embedding. That combined state is used for both LLM generation and auxiliary tag prediction heads.

Stage 5: Evaluation

graph LR A[Prompt for active sample] --> B[Deterministic generation] B --> C[Parse Next Step / MCP Tools / Explanation] C --> D[Normalize labels] D --> E[Step exact match] D --> F[MCP exact set + micro F1]

Evaluation Input

Uses the same active sample prompt built from:
- graph embeddings
- previous strategy
- previous strategy explanation
- previous step
- previous step explanation

Evaluation Output

Reported metrics:
- Average Reward
- Step Accuracy (Exact Normalized Tag)
- MCP Exact-Set Accuracy
- MCP Micro Precision / Recall / F1
- Both Step+MCP Exact Accuracy

Implementation Detail

evaluate.py now ignores the explanation for scoring. It compares only normalized step tags and normalized MCP tool sets, which is a better match to the actual task.
